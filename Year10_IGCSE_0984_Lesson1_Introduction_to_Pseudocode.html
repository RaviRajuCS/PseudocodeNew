Introduction to Pseudocode

Today's learning goals

By the end of this lesson, you should be able to…

Explain why algorithms need clear, unambiguous instructions.
Recognise COMMENT, DECLARE, INPUT, assignment and OUTPUT.
Recognise common data types used in simple algorithms.
Write and manually trace a short sequential algorithm.
Today's boundary: We are learning sequential algorithms only. Selection (IF) and iteration (loops) will be introduced in later lessons.
Lesson timer50:00 Use this as a guide; adjust the pace to your class.
Activity 1 · 5 minutes
5 min

Can you give instructions to a robot?

Imagine that I am a robot. Your task is to explain how to make a cup of tea. Give me instructions one step at a time.

Think

What must happen first? What equipment or ingredients are needed?

Suggest

Give precise instructions. Avoid vague words such as “some”, “a little” or “do it”.

Improve

If the robot misunderstands, make the instruction more exact.

Ask the class: What could go wrong if an instruction is unclear? Why can't a computer simply guess what we mean?

Key idea: An algorithm is a sequence of clear, logical steps used to solve a problem. Pseudocode is one way to represent those steps.

Activity 2 · 8 minutes
8 min

Discover the building blocks

Introduce each item through the example. Students do not need to memorise a long list of rules today.

Statement / conceptPurposeExample
COMMENTAdds an explanatory note. It is not executed.// Calculate the total
DECLAREDeclares a variable and its data type.DECLARE Total : INTEGER
INPUTAccepts data from the user.INPUT Number1
AssignmentStores a value in a variable.Total ← Number1 + Number2
OUTPUTDisplays information.OUTPUT Total
Data typeDescribes the kind of data stored.INTEGER, REAL, CHAR, STRING, BOOLEAN
Remember: Pseudocode is not Python and is not a programming language that a computer executes directly. It describes an algorithm in a structured, language-independent form.

Quick oral check: Which statement receives data? Which stores a calculated value? Which displays the result? Which lines are comments?

Activity 3 · 8 minutes
8 min

Teacher demonstration: Add two numbers

Problem: Ask the user for two whole numbers, calculate their sum and display the answer.

// Program to calculate the sum of two numbers

DECLARE Number1 : INTEGER
DECLARE Number2 : INTEGER
DECLARE Total : INTEGER

// Accept two numbers
INPUT Number1
INPUT Number2

// Calculate their sum
Total ← Number1 + Number2

// Display the result
OUTPUT Total
Point to the comments

They explain the purpose of sections of the algorithm. They do not change the result.

Point to the arrow

← means “assign the value on the right to the variable on the left”.

Point to the order

The instructions run from top to bottom, one after another.

Teacher prompt: What if we remove all the comments?

The algorithm still performs the same operations and produces the same result. Comments help people understand the algorithm; they are not instructions executed by the computer.

Activity 4 · 8 minutes
8 min

Become the computer: dry run

Read each instruction in order. Let students predict the values before revealing the completed trace.

DECLARE A : INTEGER
DECLARE B : INTEGER
DECLARE C : INTEGER

A ← 12
B ← 8
C ← A + B

OUTPUT C
Instruction completedABC
A ← 1212——
B ← 8128—
C ← A + B12820

Ask: What will OUTPUT C display? Answer: 20.

New term: A dry run (or trace) means following an algorithm manually and recording the values of variables as each instruction is carried out.
Activity 5 · 5 minutes
5 min

Spot and correct the errors

Work with a partner. Find the two syntax/convention errors in this example and correct them.

DECLARE FirstNumber : INTEGER
DECLARE SecondNumber : INTEGER
DECLARE Answer : INTEGER

INPUT FirstNumber
INPUT SecondNumber

Answer = FirstNumber + SecondNumber

PRINT Answer
Reveal the corrected version 
DECLARE FirstNumber : INTEGER
DECLARE SecondNumber : INTEGER
DECLARE Answer : INTEGER

INPUT FirstNumber
INPUT SecondNumber

Answer ← FirstNumber + SecondNumber

OUTPUT Answer

Corrections: use the assignment arrow ←, and use OUTPUT rather than PRINT in Cambridge Pseudocode.

Activity 6 · 11 minutes
11 min

Independent practice: write your own algorithms

Write each solution in Cambridge Pseudocode. Use meaningful variable names and include at least two useful comments in each algorithm.

Question 1 · Getting started

Write an algorithm that inputs a student's age and then displays it.

Check your answer 
// Input and display a student's age
DECLARE Age : INTEGER

INPUT Age
OUTPUT Age

Question 2 · Rectangle area

Input the length and width of a rectangle. Calculate and display its area.

Check your answer 
// Calculate the area of a rectangle
DECLARE Length : REAL
DECLARE Width : REAL
DECLARE Area : REAL

INPUT Length
INPUT Width
Area ← Length * Width
OUTPUT Area

Question 3 · Examination marks

Input three examination marks. Calculate and display their total and average.

Check your answer 
// Calculate the total and average of three marks
DECLARE Mark1 : REAL
DECLARE Mark2 : REAL
DECLARE Mark3 : REAL
DECLARE Total : REAL
DECLARE Average : REAL

INPUT Mark1
INPUT Mark2
INPUT Mark3

Total ← Mark1 + Mark2 + Mark3
Average ← Total / 3

OUTPUT Total
OUTPUT Average

Teacher note: The model answers are illustrative. Accept other logically correct solutions that follow the required Cambridge Pseudocode conventions.

Activity 7 · 5 minutes
5 min

Final challenge: five identical items

Write an algorithm that inputs the price of one item, calculates the total price of five identical items and displays the total.

Model answer 
// Calculate the total cost of five identical items
DECLARE ItemPrice : REAL
DECLARE TotalPrice : REAL

// Input the price of one item
INPUT ItemPrice

// Calculate the total cost
TotalPrice ← ItemPrice * 5

// Display the total cost
OUTPUT TotalPrice

Self-check: 5 marks

Progress guide: 4–5 marks: ready for the next challenge. 0–3 marks: revisit the worked example and complete another guided sequential exercise.

Before you leave

Be ready to explain these three ideas in your own words:

  1. What is the purpose of Pseudocode?
  2. What is the difference between a comment and an executable instruction?
  3. What does the assignment arrow ← mean?
Remember: A good programmer does not just write instructions. A good programmer writes instructions that are clear, logical and easy for another person to understand.
