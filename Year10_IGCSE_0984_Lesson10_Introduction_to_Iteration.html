Lesson 10: Introduction to Iteration

Cambridge IGCSE Computer Science 0984 · Understanding repetition in algorithms

50:00
50 minutesNew conceptNo loop syntax yet

Learning outcomes

  • Explain what iteration means in an algorithm.
  • Recognise situations where instructions need to be repeated.
  • Explain why repetition is more efficient than writing the same instructions many times.
  • Identify the statements or actions that belong to a repeated sequence.
  • Distinguish repetition for a known number of times from repetition that depends on a condition.
Our approach: Today is an introduction to the idea of iteration. We will understand the problem and the logic first. We will learn the actual Cambridge loop structures in the following lessons.

1. Recall – 5 minutes

Think about the programming structures you already know.

1. What is the main characteristic of a sequential algorithm?
2. What does selection allow an algorithm to do?
3. Which data type represents TRUE or FALSE?

2. Teacher demonstration – 10 minutes

What is iteration?

Iteration means repeating a set of instructions in an algorithm. It is useful when an action or group of actions must be carried out more than once.

Everyday example 1: Attendance

A teacher checks each student's name on a class register. The same checking action is performed for each student.

Everyday example 2: Quiz

A quiz program asks a question, receives an answer and checks it. This process may happen for several questions.

Everyday example 3: Shopping

A cashier enters the price of each item in a basket. The same input-and-add process is performed for every item.

Why not write the same instructions repeatedly?

Imagine displaying the numbers 1 to 5 using only sequential instructions:

OUTPUT 1 OUTPUT 2 OUTPUT 3 OUTPUT 4 OUTPUT 5

This works for five numbers, but what if we need to display 100 numbers? Writing 100 separate OUTPUT statements would be lengthy and difficult to maintain.

An algorithm can instead describe the repeated action once and specify how the repetition is controlled. We will learn the exact Pseudocode syntax for this in the next lessons.

Two common reasons for repeating instructions

Known number of repetitions

The number of repetitions is decided in advance. Example: display a message exactly 10 times.

Condition-controlled repetition

Repetition continues until a condition changes or is satisfied. Example: keep asking for a password until the correct one is entered.

Key idea: Repetition needs a control mechanism. The algorithm must have a clear way to determine how many times to repeat or when repetition should stop. We will examine these mechanisms separately.

3. Interactive exploration – 10 minutes

Activity A: How many repetitions?

Choose the most suitable description for each situation.

1. Print “Welcome” exactly 8 times.

2. Ask a user to enter a password again until it is correct.

3. Process every student in a class list containing 25 students.

4. Continue asking for a number until the user enters 0.

Activity B: Repetition simulator

Suppose we want to display a message a fixed number of times. Select a repetition count and run the simulator.

The repeated output will appear here.
The simulator demonstrates the idea of repetition. It is not asking you to write a loop yet. We will translate this logic into Cambridge Pseudocode in the next lessons.

4. Formal practice – 15 minutes

Answer in your own words. Focus on explaining the algorithmic thinking rather than writing loop syntax.

Task 1 – Explain the need for iteration

A program must display the message "Good morning" 30 times. Explain why iteration is more suitable than writing 30 separate OUTPUT statements.

A repeated sequence avoids unnecessary duplicated statements, makes the algorithm shorter, easier to read and easier to modify. The message is written once in the repeated sequence rather than 30 times.

Task 2 – Identify the repeated actions

A program processes 20 student marks. For each student, it inputs a mark and adds that mark to a running total. Identify the two actions that need to be repeated and explain when the repetition should finish.

Repeated actions: input one student's mark; add the mark to the running total. The process finishes after all 20 student marks have been processed.

Task 3 – Known count or condition?

For each situation, state whether the number of repetitions is known in advance or whether repetition depends on a condition.

  1. Display the numbers from 1 to 12.
  2. Keep asking for a valid age until the user enters a value from 0 to 120.
  3. Process 15 products in a stock list.
  4. Continue a game until the player chooses to quit.
1. Known count. 2. Condition-controlled. 3. Known count. 4. Condition-controlled.

Task 4 – Plan an algorithm in plain English

Plan an algorithm that asks a student for 5 test scores, adds them together and displays the total. Do not write loop syntax. Describe the steps in plain English and identify which steps are repeated.

Set a total to zero. Repeat the following actions for each of the five scores: ask for a score, receive the score and add it to the total. After all five scores have been entered, display the total.

5. Assessment and feedback – 10 minutes

Enter your full name and answer all six questions.

1. What is iteration?
2. Which is an example of a known number of repetitions?
3. Which is an example of condition-controlled repetition?
4. Why is iteration usually better than writing the same statements many times?
5. A program processes a class list with exactly 24 students. Which description best fits the number of repetitions?
6. What must an iterative algorithm make clear?

Teacher checkpoint

  • Students can explain iteration in their own words.
  • Students can identify the repeated group of actions in a problem.
  • Students distinguish a known repetition count from condition-controlled repetition.
  • Students understand that an iterative algorithm needs a clear control and stopping mechanism.
  • Students are ready to learn the first formal iteration construct.
