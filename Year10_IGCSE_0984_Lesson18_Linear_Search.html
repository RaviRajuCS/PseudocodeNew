1. Recall — Array traversal

In the previous lesson, we used a FOR…NEXT loop to visit every element of an array.

FOR Index ← 1 TO 6
    OUTPUT Values[Index]
NEXT Index

In a search, instead of simply outputting every element, we compare each element with a value we are looking for. That value is called the search item or target.

2. Teacher demonstration — How linear search works

Suppose the array contains these six values and we want to find the number 27.

Index 114
Index 227
Index 39
Index 442
Index 527
Index 618
  1. Start at index 1.
  2. Compare the current element with the target.
  3. If they are not equal, move to the next index.
  4. If they are equal, the target has been found.
  5. Stop when the target is found or the end of the array is reached.

Here, the first 27 is found at index 2. The search can stop there if the task asks for the first occurrence.

Important terms

Target / search item
The value being searched for.
Index
The position currently being checked.
Found flag
A BOOLEAN variable indicating whether the target has been found.
Position
The index where the target is found.

3. Worked example — Linear search using WHILE…DO

The following algorithm searches an array of six INTEGER values. It records the position of the first occurrence of the target.

DECLARE Values : ARRAY[1:6] OF INTEGER
DECLARE Index : INTEGER
DECLARE Target : INTEGER
DECLARE Found : BOOLEAN
DECLARE Position : INTEGER

Found ← FALSE
Position ← 0
Index ← 1

INPUT Target

WHILE Index <= 6 AND Found = FALSE DO
    IF Values[Index] = Target THEN
        Found ← TRUE
        Position ← Index
    ENDIF
    Index ← Index + 1
ENDWHILE

IF Found = TRUE THEN
    OUTPUT "Found at position ", Position
ELSE
    OUTPUT "Not found"
ENDIF

For this worked example, assume the array has already been populated. The search begins at index 1. The variables Found and Position are initialised before the loop.

Understanding the control variables

VariablePurposeInitial value
IndexTracks the array element currently being checked.1
FoundRecords whether the target has been located.FALSE
PositionStores the index where the first match occurs.0 (means no position recorded yet)
TargetStores the value entered by the user.Input by user

Trace table — Search for 27

Output: Found at position 2.

Why stop at the first match? This algorithm is designed to report the first occurrence. If the target appears again later, those later positions are not checked after Found becomes TRUE.

4. What if the target is not present?

If the search reaches the last element without finding the target, Index becomes 7. The condition Index <= 6 is FALSE, so the loop ends. Found remains FALSE and the algorithm outputs “Not found”.

IF Found = TRUE THEN
    OUTPUT "Found at position ", Position
ELSE
    OUTPUT "Not found"
ENDIF

Initialising Found ← FALSE is essential. Otherwise, the algorithm may use an undefined or incorrect flag value.

6. Common errors to avoid

Not initialising Found
Set Found ← FALSE before starting the search.
Wrong loop bounds
For ARRAY[1:6], check indexes 1 to 6, not 0 to 6.
Not moving to the next index
Increment Index when the current element has been checked.
Confusing index and value
Position is the index; Values[Index] is the stored value.

Efficiency idea: A linear search may need to check every element if the target is at the end or is not present. For an array of six elements, it checks at most six elements.

Lesson summary

  • Linear search checks array elements one by one.
  • The target is compared with the current element.
  • A Boolean Found flag records whether a match has been found.
  • An index variable tracks the current position.
  • The search ends when the target is found or the end of the array is reached.
  • This method works whether or not the array is sorted.
